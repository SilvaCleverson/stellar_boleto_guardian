O problema

Empresas e agentes automatizados recebem dados de boleto o tempo todo — de um ERP, de um sistema de cobrança, de um e-mail, de outro agente. Antes de confiar ou de pagar, é preciso uma verificação de integridade independente: os dados que chegaram são os mesmos que o emissor registrou?

Hoje essa verificação é cara de montar: exige contrato comercial, credencial, chave de API, plano mensal. Para um agente que faz uma consulta, isso é atrito demais — e o resultado prático é que a conferência simplesmente não acontece.

Uma verificação deveria custar o preço de uma verificação. Nem contrato, nem assinatura, nem onboarding.

Dados sem procedência

O boleto chega ao ERP sem prova de que não foi alterado no caminho.

Atrito de credencial

API key e assinatura mensal para quem só precisa de uma consulta.

Custo não mensurável

Sem preço por chamada, não dá para atribuir o custo da verificação ao processo que a pediu.

Agentes sem meio de pagar

Um agente de IA não abre conta, não assina contrato e não guarda cartão.

A solução: Guardian402

Guardian402 é uma API pay-per-use: cada chamada de verificação custa 0,01 USDC, cobrada pelo protocolo x402 na Stellar. Não há API key, não há assinatura, não há cadastro. O cliente chama, recebe um HTTP 402 com as instruções de pagamento, liquida e recebe a resposta.

A verificação é baseada em hash: o serviço recalcula a impressão digital dos campos do boleto recebidos e compara com a prova de integridade registrada em um contrato Soroban. Nada além do hash precisa estar on-chain.

Uma verificação — de qualquer ERP ou agente — é um pagamento em USDC mensurável.

Por que é diferente

Preço por chamada, não por contrato

0,01 USDC por verificação, liquidados na hora via x402.

Agnóstico de ERP

Funciona com qualquer origem que envie os campos esperados. TOTVS Protheus é o caso de referência, não um requisito.

Prova on-chain, não banco de dados

A referência de integridade vive em um contrato Soroban público e auditável.

Pronto para agentes

Um agente de IA paga e consome o endpoint sozinho — sem onboarding humano.

Como funciona

Da chamada do ERP ou do agente até a resposta lida do Soroban, em quatro passos:

1

Chamada

POST /v1/verify com os campos do boleto, como um ERP ou agente enviaria.

2

HTTP 402

A resposta traz as instruções de pagamento x402.

3

Liquidação

O cliente autoriza e liquida 0,01 USDC na Stellar Testnet.

4

Resposta

Retorna AUTHENTIC, MISMATCH, NOT_FOUND ou REVOKED, lido do Soroban.

Respostas possíveis

AUTHENTICOs dados batem com a prova de integridade ativa registrada on-chain.
MISMATCHO identificador existe, mas os dados do boleto enviados divergem.
NOT_FOUNDNão há prova registrada para aquele identificador de boleto.
REVOKEDA prova existiu e foi revogada pelo administrador emissor.

Guardian402 verifica se os dados enviados batem com uma prova de integridade previamente registrada. Ele não confirma liquidação bancária nem status de pagamento.

Por que o Protheus aparece nos exemplos

A TOTVS é a maior empresa de software de gestão do Brasil, e o Protheus é o ERP onde boa parte das empresas brasileiras emite e administra boletos. Na pesquisa anual de TI da FGV-Eaesp, a TOTVS detém cerca de 34% do mercado brasileiro de ERP (empatada com a SAP) e cerca de 50% nas implantações menores (até ~180 usuários).

Isso faz do Protheus o caso de referência natural para demonstrações no Brasil. O Guardian402, porém, não exige Protheus: a mesma checagem por hash vale para dados de boleto vindos de qualquer ERP, sistema de cobrança ou agente que envie os campos esperados.

Fonte: Pesquisa Anual do Uso de TI da FGV-Eaesp (participação de mercado de ERP no Brasil).
